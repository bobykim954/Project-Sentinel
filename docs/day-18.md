# Day 18 - Live Event Dashboard

**Date:** October 8, 2026

## Goal

The goal for Day 18 was to make the Project Sentinel event dashboard usable as a live local monitoring interface instead of only a static report.

Previously, the dashboard had to be regenerated manually after new events were added. The new local dashboard server automatically regenerates the dashboard when it is requested by the browser.

## What Was Added

A new file was created:

```text
src/dashboard_server.py
```

The server uses Python's built-in HTTP server and does not require Flask or another external web framework.

It runs locally at:

```text
http://127.0.0.1:8000
```

The dashboard is available at:

```text
http://127.0.0.1:8000/reports/event-dashboard.html
```

## How It Works

The live workflow is:

```text
Camera
   ->
Sentinel
   ->
data/events.csv
   ->
Dashboard Server
   ->
Event Dashboard
   ->
Browser
```

When the browser requests the dashboard, the server regenerates the dashboard from the latest event history.

The generated page also refreshes automatically every five seconds.

This means newly completed events can appear in the dashboard without manually running:

```text
python src/event_dashboard.py
```

## Event Integration

The live dashboard continues to use the same event data generated by Sentinel and the same priority engine used during Day 16.

This keeps the data flow consistent:

```text
Detection
   ->
Event History
   ->
Priority Analysis
   ->
Dashboard
```

The dashboard does not create separate event records.

## Local-Only Design

The dashboard server is intentionally local.

It uses:

```text
127.0.0.1
```

and Python's standard library HTTP server.

No external cloud service or internet connection is required for the dashboard itself.

This fits the original offline-first direction of Project Sentinel.

## Important Limitations

The current implementation is a lightweight development server, not a production web server.

The dashboard refreshes periodically rather than using WebSockets or another continuous real-time connection.

The dashboard is still generated from the CSV event history, so an event appears after it has been written to the event history rather than as soon as detection begins.

The current system is designed for local development and testing and has not yet been hardened for remote network access.
